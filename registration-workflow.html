Grok 帳戶自動註冊完整流程

Grok API Pool 指南 · 附錄 B 詳細版

本頁完整說明「Grok 帳戶自動註冊系統」從 Cron 觸發到成功匯入 grok2api 的全流程。

包含每個步驟執行的 script、讀寫檔案、瀏覽器自動化、郵件驗證、Token 提取、帳戶儲存與 Admin API 匯入。最後補充 2026-08-07 實測後加入的智能調度工具鏈。

整體流程架構

Cron (04:00 / 16:00)
  ↓
~/.hermes/scripts/grok-pool-batch.sh
  ↓
~/grok-pool/cron-batch.sh 5
  ↓
~/grok-pool/grok-pool-register.sh 5 1
  ↓
  ├─ 產生 accounts_*.txt
  ├─ browser_runtime.py + DrissionPage（自動註冊 + 郵件驗證 + Token 提取）
  ├─ 解析 Token 並呼叫 grok2api Admin API 匯入（僅 console，web 已停）
  └─ 寫入 logs/batch_*.log
  ↓
pool-status.py（每分鐘更新 status.json）
  ↓
儀表板顯示最新批次 + 配額
  ↓
smart_gateway.py（智能調度：熔斷 + 速率整形 + 降級鏈）
  ↓
poc_agent.py（端到端 ReAct 查詢）

完整端到端流程（12 步驟）

1

Heremes Cron 觸發

執行檔：~/.hermes/scripts/grok-pool-batch.sh

每日在 04:00 及 16:00 由 Hermes cron 機制啟動，預設每批註冊 5 個帳戶。

讀取：無
產生：無
2

批次包裝執行

執行檔：~/grok-pool/cron-batch.sh

接收參數（預設 5），呼叫主註冊腳本，並將輸出寫入 log。

讀取：無
產生：logs/cron_*.log
3

主註冊腳本啟動

執行檔：~/grok-pool/grok-pool-register.sh

負責整個註冊流程的 orchestration，包含產生帳戶檔、呼叫瀏覽器自動化、解析 Token、呼叫 Admin API 匯入。

讀取：config、環境變數
產生：accounts_YYYYMMDD_HHMMSS.txt
4

瀏覽器自動化註冊

執行檔：~/grok-pool-register/browser_runtime.py + cpa_xai/browser_session.py

使用 DrissionPage 啟動 Chromium，前往 console.x.ai 進行註冊、處理郵件驗證、登入並提取 SSO Token。

讀取：config.json、proxy 設定
產生：瀏覽器 session、驗證郵件
5

郵件驗證處理

瀏覽器自動化會自動打開郵件驗證連結（或模擬點擊），完成帳戶啟用。

6

登入與 Token 提取

驗證成功後自動登入 console.x.ai，提取 SSO Token 存入 accounts_*.txt 的第 3 欄。

產生：accounts_*.txt（格式：email ---- password ---- token）
7

解析帳戶檔

grok-pool-register.sh 讀取 accounts_*.txt，解析出 email / password / token。

8

grok2api Admin API 登入

使用 admin 帳號登入 grok2api，取得 access token。

POST /api/admin/v1/auth/login
9

帳戶匯入 grok2api（僅 console）

呼叫 Admin API 的 import endpoint，將 SSO Token 匯入為 console 帳戶。

⚠️ 2026-08-07 起停止匯入 web 帳戶：實測發現 web 路線在資料中心 IP 會被 anti-bot 挑戰擋死（plane:web stage:anti_bot_retry client_error），註冊成本白花，且同一 team fingerprint 會拖慢 console 帳戶。現僅匯入 console（anti-bot 可繞過、能出真內容）。

POST /api/admin/v1/accounts/console/import（multipart form）
10

寫入執行 Log

所有輸出寫入 logs/batch_*.log，包含成功 / 失敗 / 匯入數量。

11

健康監察更新

pool-status.py 每分鐘執行，更新 web/status.json，包含最新批次與配額。

12

儀表板顯示

系統監察頁每分鐘自動刷新，顯示最新批次結果與配額 gauge。

2026-08-07 實測：智能調度工具鏈（下半場）

背景 / Rationale
實測發現兩條硬性約束，決定池嘅使用方式：
  • Team Fingerprint RPM 硬鎖：所有 console 帳戶共享同一 team 指紋，grok-4.3 上限約 60 RPM（log 可見 upstream_team_model_rate_limited，例如 actual=278 / limit=60）。加帳戶無法突破，只能靠隊列整形 + 降級。
  • Web 路線在 DC IP 全滅：web 池（fast/auto）雖然有配額，但 anti-bot 擋死資料中心 IP，grok-chat-fast 回 upstream_unavailable。
因此正確策略 = 「有限資源智能調度」：用正確的模型做正確的事，而非無限並行。
重要發現：grok2api 支援原生 tool-calling
實測 grok-4.3 完整透傳 OpenAI tools 參數，回傳 finish_reason:"tool_calls" 及真實 function call JSON。唔需要手寫外層 planner / constrained prompting——Hermes 原生 agent loop 已經可以驅動池做真 agent。
13

智能調度閘道（smart_gateway.py）

執行檔：~/grok-pool/tools/smart_gateway.py

三合一閘道：熔斷器（連續 3 次故障自動 OPEN，429 唔當故障）+ Token Bucket 速率整形（premium 60 RPM / standard 100 RPM）+ 智能路由（tier 分類 → 模型選擇 → 降級鏈）。

命令：python3 smart_gateway.py check（健康檢查）· route "問題"（路由測試）· ask "問題"（端到端）
讀取：GROK_POOL_API_KEY、模型池定義
降級鏈：light→4.20-non-reasoning → 4.3 → 4.5；heavy→4.3 → 4.5 → 4.20
14

端到端 ReAct PoC（poc_agent.py）

執行檔：~/grok-pool/tools/poc_agent.py

示範池可以驅動工具做「真 agent」：Grok 揀工具（search / parse_page）→ 外層 Python 執行（DuckDuckGo + 純文本抽取）→ 回傳結果 → Grok 給最終答案。實測「香港今日新聞三大事件」成功輸出附來源連結嘅完整答案。

命令：python3 poc_agent.py "問題"
15

429 / 熔斷即時監控（gateway_monitor.py）

執行檔：~/grok-pool/tools/gateway_monitor.py

透過 docker exec 查 request_audits 表 + docker logs，即時統計 429 率、console 枯竭數、team fingerprint RPM 鎖狀態。

命令：python3 gateway_monitor.py（簡潔狀態）· --json（詳細）· --watch（每 60s）
16

驗收測試（verify_phase1.py）

執行檔：~/grok-pool/tools/verify_phase1.py

8 項單元測試，唔打真實 API：熔斷器行為（429 唔熔斷 / 3 次故障 OPEN / 退避恢復）、Token Bucket 60 RPM 整形、分類器準確率、路由唔 crash。

命令：python3 verify_phase1.py（期望 8/8 通過）

關鍵技術點

瀏覽器自動化
使用 DrissionPage + Chromium，自動處理註冊、郵件驗證、登入、Token 提取。cron 環境需額外掃描 Chromium 路徑。
帳戶儲存格式
email ---- password ---- SSO_TOKEN（三欄以 ---- 分隔）
grok2api Admin API 匯入
必須使用 multipart form 上傳檔案，raw body 會回 invalidAuthFile。
